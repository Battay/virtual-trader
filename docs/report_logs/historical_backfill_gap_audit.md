## Methodology

This was a local, read-only audit of `data/metadata/backfill_state.json`, `data/raw/html`, and `data/raw/csv`. The audited population is the union of the state's `temporary_skips` and `failed_dates`; the two sets do not overlap. Attempt counts, response byte sizes, and recorded raw paths come from `attempt_records`. When needed, matching local `market_YYYY-MM-DD*.html` files were also inspected. The reported raw byte size is for the latest locally discovered raw response for that date.

HTML evidence uses the official historical table marker `#historicalTable` and the project's parser selector `tr[data-type="equity"]`. CSV validity and row counts use the existing `valid_daily_csv_row_count()` validator, including required columns and exact requested-date matching. No empty response was treated as proof of a holiday. “Possible holiday/non-trading candidate” is pattern-only wording.

Each date is assigned exactly one primary group using this precedence: valid CSV (A), failed state (E), weekend (D), missing/no historical table (F), repeated recorded 903-byte empty tables (B), other empty historical-table candidate (H), other temporary pattern (C), fallback manual review (G). Thus the group counts reconcile without overlap.
